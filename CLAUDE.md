# Evens: notes for Claude sessions

Owner: Joseph (manages everything from his phone via the Claude app). Plain English, UK betting terms, decimal odds by default.

## Layout
- `engine/`: Python, run daily by `.github/workflows/refresh.yml`
  - `oddspapi.py` API client. NEVER write the raw `/account` payload anywhere: it contains the API key and email, and this repo is public.
  - `budget.py` free plan is 250 requests/month. Costs: fixtures list 1; Pinnacle `odds-by-tournaments` 1 per 5 tournaments (hard API limit) and exactly one bookmaker per call; per-match `/odds` 1 each (returns all bookies).
  - `catalog.py` leg keys, OddsPapi market/outcome IDs, settlement rules
  - `legs.py` fair probabilities (Pinnacle de-vig: power method) and per-bookie edges
  - `goals_model.py` Dixon-Coles on football-data.co.uk; `names.py` team-name matching
  - `builder.py` slips: one bookie, different matches, kick-off window, odds band
  - `settle.py` track record + calibration; `run.py` orchestrates
  - `scores.py` live scores + 90-minute results, run by `.github/workflows/scores.yml` (cron every 10 min 11:00–23:59 UTC, but GitHub actually starts it every 40–50 min, so each run loops every 5 min for up to 50 min while a match is live; API-Football at most every ~10 min, football-data.org in between; own concurrency group `live-scores`). Calls nothing unless a tracked fixture is live or awaiting a result. Feeds: API-Football (secret `API_FOOTBALL_KEY`, 100/day, `/status` free; free plan may refuse the current season, in which case it stops for the day and notes it in `live.json` `feeds`) and football-data.org (secret `FOOTBALL_DATA_API`, 10/min, 12 big competitions, slightly delayed). NEVER write the API-Football `/status` account block (it has the email). Writes `docs/data/live.json` and `data/scores_state.json`, and re-settles `history.json`; the morning run also settles from `scores_state.json` before falling back to football-data.co.uk.
- `docs/`: static PWA on GitHub Pages (`index.html`, `app.css` tokens in `:root`, `app.js`, `telly.js` for the third room). Reads `docs/data/latest.json`, `history.json` and `live.json` (re-checked every 90s while open).

## Coverage and rationing (7 Nov 2026, Joseph's priorities)
Must-haves: Premier League and NFL whenever they're on; then Championship; then whatever else is on at the same time or evening (NBA; MLB is out of season until late March). `config/settings.json` `core`: one `odds-by-tournaments` request per bookie covers every game in up to 5 competitions (days ahead), so core groups (Prem 17, NFL 31, Championship 18, NBA 132, FA Cup 19) are fetched first for Pinnacle + `core.books` (Bet365, Paddy Power, William Hill, Unibet, Ladbrokes), on the weekdays listed per group. If OddsPapi refuses mixed sports in one request, `fetch_core` splits by sport. Leftover allowance goes to Pinnacle for other football leagues and per-match calls (all bookies) via `shortlist` (`priority` = Prem, Championship first). Weekday weights favour Fri–Sun. `--calls N` / workflow input `calls` lets a by-hand run spend N requests. NFL/NBA legs: `catalog._us_defs` (keys `nfl-ml:1`, `nfl-sp:2:+7.5`, `nba-tot:220.5:over`, from `data/ref/markets_{14,11}.json`); team names `data/ref/participants_{sport}.json`. US legs are not auto-settled yet (needs API-Sports american-football / nba scores, same key, free plan serves the 2026 season). Discovery: `task=sports` (`engine/probe_sports.py`, ~9 requests).
- Bet365 and William Hill: OddsPapi flags their match markets `marketActive: false` even when current (only player props are 'active'). `lenient_books` keeps their prices if changed in the last 18h; `latest.json` books carry `check: true` and the ticket tells Joseph to check prices in the bookie app.

## NFL player engine (7 Nov 2026; plan: project doc `claude/evens-player-engine-plan.md`)
- `engine/nfl/`: `data.py` downloads nflverse (weekly player/team stats, schedules with lines, snaps, injuries) to `data/cache/nfl` (not committed). `model.py`: stats-only projections, *team volume x share x efficiency x opponent-by-position*; volume regression on team rate, defence faced, margin and team total (`data/nfl_model/params.json`); spread of outcomes from the walk-forward miss table `data/nfl_model/ratios.json`. `backtest.py` (`task=nflbacktest`): fits 2023-24, tests 2025 (`data/nfl_model/backtest.json`). Tuned 7 Nov (on 2024, confirmed on unseen 2025): fixed a share-shrinkage bug that projected receivers/RBs ~45% low; `opp_power` (defence weight) rec 0.75 / rush 1.0 / pass 0.75 (heavier weighting tested worse); `hl_def` 3 (recent defensive form); `mom_gamma` (last-3 form vs baseline) rush 0.25 only (hurt rec/pass); `home_mult` pass 1.03, rec 1.01; backups who played earlier in the season stay available and receivers drop with a weaker QB (`qb_factor`, capped at 1). Injury signals (`q_mult`, `return_mult`): Questionable this week rec 0.88 / rush 0.92 / pass 0.88; first game back after missing the team's last game 0.92 / 0.96 / 0.92 (measured 2024, confirmed 2025). Players facing the worst defences already come in below projection relative to the best, so defence weight was NOT raised. 2025 typical miss: receiving 18.4 vs 19.5 recent average, rushing 18.9 vs 20.0, passing 59.4 vs 64.3; confident calls hit ~69-70%; slightly over-confident above 65% (`CAL_SHRINK` 0.85). Team spread/total model does NOT beat closing lines (margin miss 10.3 vs 9.9; ATS 48% when it disagrees by 3+), so spread/total stay priced off Pinnacle.
- `live.py` (called from `run.execute`): matches OddsPapi NFL fixtures to nflverse games, removes Out/Doubtful players (70% of their share to teammates), anchors each player's centre to Pinnacle's main prop line (75% market / 25% model; UK two-way average 50/50; model alone otherwise; skip if they differ >45%), prices every offered line incl. alt lines. Legs key `nfl-prop:{rec_yds|rush_yds|pass_yds}:{gsis_id}:{line}:{over|under}`, with `short` and `why`. Writes `docs/data/projections.json` (who's going to do what). Settlement from nflverse scores/player stats next morning (`results_and_props`, `settle._prop_result`; no stat line in a final game = void). `data/nfl_model/fixture_map.json` maps OddsPapi fixture ids to nflverse game ids (with `flip` for neutral sites).
- Line pricing (`live._p`), tested 7 Nov 2026: 30,000+ walk-forward 2025 outcomes over lines 4.5–99.5 (rec/rush) and 149.5–299.5 (pass) showed the raw miss-table probabilities were already calibrated 3–97% (e.g. said 92%, came 92%). So no shrink and no narrowing; only a tiny per-stat logistic correction (`data/nfl_model/calibration.json`, fitted on 2024+2025; fitted on 2024 alone it left 2025 log loss unchanged). Don't re-add CAL_SHRINK/TIGHTEN: narrowing receiving squeezed out zero-catch games, and narrowing passing went the wrong way.
- **Card table** (second room, `#table`; Hold'em version 7 Nov 2026 after Joseph found blackjack's bust impractical): NFL player props only. `SLOTS | TABLE` switcher on both rooms plus a sideways swipe from mid-screen (`roomSwipe`, not from the 24px edges, not on reels/lever/chip rows/hands/board). State in localStorage `evens.table` `{book, games, hand, hole, active, copied}`. Cards = `nfl-prop` legs at the table's bookie (own choice; default your bookie else most lines), price 1.03–1.6, chance ≥55%; `score` = exp(25×edge) × confidence (Pinnacle-anchored 1, UK-anchored 0.8, model 0.55) × sweet-spot fit. **Dealer's hands** (`dealerHands`): every 2–5-card, one-per-match combo in the evens zone around your **hole cards** (☆ on any board or hand card), top 12 matches × 4 cards each, shown as Best value / Safest / Fewest cards. **Board** = best 12 cards (one per player and stat). Hand: tap a dealer hand, a board card or a projections line; Hit (best card that keeps you ≤2.30), ↻ Swap line (next line in the same match), Fold. No bust: Short / ✓ Evens / Over · fold one. **Deck selector** sheet: matchups grouped by kick-off slot, team-colour badges with codes (`NFL_COL`; no logos). Look: hanging lamp (`#lamp`, `--swing` from a damped spring: idle sway + `deviceorientation` tilt + a nudge on each deal), original 24×24 pixel-art croupier (`DEALER_IDLE`/`DEALER_DEAL`: visor, moustache, bow tie, sleeve garters) who deals; his speech bubble explains the current state (`bubbleText`) and tapping him cycles `TIPS`. Dealer's hands show what each is for and labelled pays / lands / edge with 'Lay it down ›'; 'On the board' is a `<details>` collapsed by default; reduced motion = no swing or flicker. Landscape (max-height 560px): two-column oval. Copy / Placed it log the hand; it settles from `history.json` `leg_results`.
- **Card table round 4** (8 Nov 2026, project doc `claude/evens-round4-handoff.md`): **deal and fold**. `tableSlots()` clusters the deck's games into kick-off slots (≤30 min apart); slots with 2+ games get a row of dealer's hands (Early doors / Late games / Night games; one-game slots listed as "Not dealt"; if no slot has 2 games, one "Across the day" row). `dealerRows()` searches every bookie in `tableBooks()` per slot (`searchHands`) and shows Best value / Safest (+ Fewest cards if fewer cards); each hand carries its bookie, and laying it sets `table.book` and `table.slot`. **Fold** (visible on every card) removes the card, adds the player to `table.folded`, and `nextCard()` deals the best card from the same slot and bookie that keeps you ≤2.30 (preferring ≥1.90); Hit uses the same picker (random among top 3). ☆ is now "always include" (still `table.hole`), only in On the board, which moved below the actions. Swap line and "Make it a pick" are gone. Cards: no overlap, open card shows We expect / Real chance / Edge tiles, `whyRows()` splits `why` into Role / Defence / Form / Venue / News rows (also used in Who's going to do what), and a source line. Dealer bubble: 4 tips with page dots (`tips()`, the third compares bookies live for the first slot) or `sayMsg` (what just happened) / `stateLine()`. Look: wood rail with brass rivets and gold piping (layered `border-box` backgrounds on `.felt`), felt grain, smaller lamp, printed gold arc text (`.felt-arc`). Landscape: `.t-play-area` wraps the hand side. State `evens.table` adds `folded`, `slot`, `open`.
- Sound (8 Nov 2026): iPhones mute Web Audio with the silent switch unless `navigator.audioSession.type = "playback"` (set before the AudioContext is made; older iOS gets a silent `<audio>` blip in the tap). Unlock listens on pointerup/click/touchend (a touch pointerdown isn't a user gesture) until the context runs, re-arms on returning to the app, and `tone()` resumes a suspended context.
- Props come from the same OddsPapi payloads (`parse.add_props`, market types in `PROP_TYPES`): no extra requests. Pinnacle prop prices update rarely, so props keep prices changed within 96h.

## Round 5 (10 Nov 2026; project doc `claude/evens-round5-handoff.md`)
- **Settlement bug fixed** (`settle.settle`): the slip loop reused the name `results` for a slip's leg outcomes, replacing the scores lookup with a list. From then on no later slip or tracked leg could find a score, so one slip stuck on a leg with no result (an FA Cup tie after API-Football was suspended) blocked the whole record: 21 of 26 slips pending, `calibration` and `leg_results` empty. Regression test `test_one_stuck_slip_does_not_block_the_rest`. The next scores or morning run back-fills about 2,150 legs. Slips with an NBA leg still can't settle (no NBA results feed; they turn `unsettled` after 10 days): needs Joseph's decision.
- **Trust** (`engine/trust.py`, `config/settings.json` `trust`, published as `latest.json` `trust`; mirrored by `believed()` in app.js): a positive claimed edge is shrunk before ranking or display: trust(source) x (first 3% in full + a quarter of the rest); sharp 0.8, sharp-derived 0.7, sharp+model 0.5, consensus / market+model 0.4, model 0.25. Edges at or below zero are untouched. Why: on the first weekend's 2,148 settled legs, those claiming over +5% (avg +13%) returned +2%, and +1% to +5% returned -5%. `builder` ranks slips by believed EV (`ev_trust`); `ev` and `hit_p` stay raw so the record still tests the raw model. In the app `applyTrust()` rewrites every pool leg's `fair_p` and `edge` to the believed values at load (raw kept as `fair_claimed`, `claimed`), so spins, Build a bet, the min-edge filter and the ticket all use them; card-table cards do the same in `card()`.
- **Evidence** (`settle._evidence`, `history.json` `evidence`): running sums per claimed-edge band (`big` >5%, `some` 1-5%, `flat` -3 to 1%, `poor`), fair-price source and market: n, wins, p_sum, implied_sum, claimed_sum, return_sum. Leg snapshots now carry `source` (legs tracked before 10 Nov have none and count as `unknown`). Revisit the trust numbers once each row has a few hundred legs.
- **Ticket** (`ticketNotes`): what the bet is worth on average in pence (stake x believed edge), how many legs are checked against Pinnacle, and a price check: if another of your bookies prices every leg and pays over 1% more, "Same legs pay 2.06 at Ladbrokes" with Switch (`switchBookie`, with Undo in the status slot).
- **Chance now and fair cash-out** (`legChanceNow`, `betNow`): football legs in play use Poisson goals for the share of the game left (rates from the fixture's `model` xG, else 1.45/1.2), settled over every final score with `settleKey`, then shifted in log-odds by the gap to the pre-match fair chance, fading with time left. NFL/NBA/player legs keep their pre-match chance until decided ("about"). Shown in sweat mode's payline, on each live reel ("63' · 38%"), in Winnings and on the telly. Also fixed: sweat mode's payline was being overwritten by the machine's fair-price line (`clearStatus()` ran after it was set).
- **The Telly** (third room `#telly`, `docs/telly.js`, font VT323 self-hosted, OFL): a pub TV showing teletext. P302 What's on (`tellySessions`: kick-off windows grouped into non-overlapping sessions, the best slip across your bookies for each via `bestSlipFor`, a verdict from the believed edge: Worth a spin >= +1%, Fair game, Thin, Swerve < -3%; tap loads it on the machine; the card table's dealt rows are listed too), P303 Your bets (scores, each leg's chance, chance now, fair cash-out), P304 The form (luck vs expectation, Did the edge show up?, whose prices to trust, by market, bookie league table from today's prices). Fastext buttons switch pages. `ROOMS = [home, table, telly]` drives the switcher and the sideways swipe. Settings: "Open the app on" (`prefs.start_room`). Manifest has shortcuts (What's on, My bets).

## Facts learned from the live API (Nov 2026)
- Sky Bet and William Hill are not in OddsPapi data. `odds-by-tournaments` for bet365 returns very thin markets; use per-match `/odds` for UK books.
- 4xx responses still count against the quota.
- Market IDs: 101 1X2, 101902 double chance, 10214 DNB, 106/108/1010/1012/1014 totals 0.5–4.5, 10224/10240 team over 0.5, 10284/10286 team to score, 104 BTTS, AH market 1084 = home +1.5, 1060 outcome 1061 = away +1.5.

## Working rules
- Test before pushing: `python -m pytest -q tests`; offline run with `tests/make_mock.py` + `engine.run --mock` (writes to /tmp).
- Scores check by hand: `gh workflow run scores.yml -R JONeillio/evens-model` (calls both feeds once). Offline: `python -m engine.scores --mock DIR --root OUT --now ...` (see `tests/test_scores.py`).
- Live runs cost requests. Trigger with `gh workflow run refresh.yml -R JONeillio/evens-model` only when needed; `-f task=probe` costs 1.
- Rebuild on GitHub with no odds requests (e.g. after engine changes): `gh api -X POST repos/JONeillio/evens-model/actions/workflows/refresh.yml/dispatches -f ref=main -f 'inputs[task]=rebuild'`. (`gh workflow run` fails here: no GraphQL.)
- Rebuild the app's data offline with no API calls: copy `data/snapshot.json` to `OUT/data/` and run `python -m engine.run --reuse-snapshot --out OUT`.
- Joseph asked to be consulted before switching odds provider.
- Bump `VERSION` in `docs/sw.js` whenever app files change so phones pick up the update.
